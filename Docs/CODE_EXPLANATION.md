# CyberLearner — Code Explanation

This document explains how the CyberLearner code is organised, how a request flows through it, and why each part is written the way it is. Read the general sections first, then the section for your own member area.

---

## 1. Big picture

CyberLearner is an **ASP.NET Web Forms** application on **.NET Framework 4.7.2** with a **SQL Server LocalDB** database.

Every page is made of two files:

| File | Contains |
|---|---|
| `Page.aspx` | The HTML markup and ASP.NET server controls (TextBox, Button, GridView, validators) |
| `Page.aspx.cs` | The C# "code-behind" that runs on the server when the page loads or a button is clicked |
| `Page.aspx.designer.cs` | Generated by Visual Studio. Declares the controls so the code-behind can use them (do not edit by hand) |

The code is split into small layers so each file has one job:

```
Browser
   │
   ▼
.aspx page + code-behind      (UI: read input, show output, handle clicks)
   │
   ▼
Services/*.cs                 (business rules: unlock topics, check exam access, 7-day rule)
   │
   ▼
Data/DatabaseHelper.cs        (one place that opens connections and runs SQL)
   │
   ▼
SQL Server LocalDB            (9 tables from Database/CreateTables.sql)
```

**Why layers?** If the SQL or a rule changes, it changes in one service, not in every page. It also matches the four-member split: each member owns their own services and pages, and the shared `DatabaseHelper` keeps everyone using the same connection.

## 3. Database access — `Data/DatabaseHelper.cs`

All SQL goes through three methods:

| Method | Used for | Returns |
|---|---|---|
| `GetTable(sql, params)` | SELECT that returns rows | `DataTable` |
| `Execute(sql, params)` | INSERT, UPDATE, DELETE | number of rows changed |
| `GetValue(sql, params)` | SELECT that returns one value (COUNT, new ID) | `object` |

Example from `AuthService.RegisterLearner`:

```csharp
string sql = "INSERT INTO Users (FullName, Email, Username, PasswordHash, Role, AccountStatus) " +
             "VALUES (@FullName, @Email, @Username, @PasswordHash, 'Learner', 'Active')";

DatabaseHelper.Execute(sql,
    new SqlParameter("@FullName", fullName),
    new SqlParameter("@Email", email),
    ...);
```

**Why written this way:**

- **Parameters (`@FullName`) instead of joining strings.** User input is never pasted into the SQL text, so SQL injection is not possible. This is a requirement in the system specification.
- **`using (SqlConnection con = ...)`** closes the connection automatically even if an error happens, so connections are not left open.
- **One connection string** is read from `Web.config` (`CyberLearnerDB`). Every member uses the same database without copying connection code into each page.
- **ADO.NET (`SqlCommand`, `SqlDataAdapter`) instead of Entity Framework.** It shows the actual SQL queries clearly, which is what the assignment asks us to explain, and it is simpler to set up.

## 4. Models — `Models/*.cs`

Each model is a plain class with properties that match a table exactly, for example `User` has `UserID`, `FullName`, `Email`, `Username`, `PasswordHash`, `Role`, `AccountStatus`, `CreatedAt`.

**Why:** The database contract requires the same names in C# and SQL, so anyone can see which column a property comes from. Services read one row into a model (e.g. `AuthService.ReadUser`) when a page needs a single record, and return a `DataTable` when a page needs a list for a GridView.

`ReviewedBy` and `ReviewedDate` in the request models are `int?` and `DateTime?` (nullable) because they are empty in the database until Management reviews the request.

## 5. Login, sessions and role protection

### Password hashing — `Security/PasswordHelper.cs`

```csharp
byte[] salt = new byte[16];
rng.GetBytes(salt);
Rfc2898DeriveBytes pbkdf2 = new Rfc2898DeriveBytes(password, salt, 10000);
byte[] hash = pbkdf2.GetBytes(32);
return Convert.ToBase64String(salt) + ":" + Convert.ToBase64String(hash);
```

- A **random salt** is created for every password, so two users with the same password get different hashes.
- **PBKDF2 with 10,000 iterations** makes guessing passwords slow for an attacker.
- The salt and hash are stored together in `PasswordHash` as `salt:hash`.
- `VerifyPassword` takes the salt back out, hashes the typed password the same way, and compares.

**Why:** The specification says passwords must never be stored as plain text, and Management must never see them. Only the hash is stored.

### Session — `Security/SessionHelper.cs`

After a successful login, `SessionHelper.SignIn(user)` saves three values:

```csharp
Session["UserID"]   = user.UserID;
Session["Role"]     = user.Role;
Session["FullName"] = user.FullName;
```

Every other page gets the current user with `SessionHelper.GetUserID()`. Logout calls `Session.Clear()` and `Session.Abandon()` so the session is destroyed.

**Why the Session and not a table?** The specification says session state is kept in ASP.NET Session and no Sessions table is added. The session also expires automatically after 20 minutes (set in `Web.config`).

### Role protection — master pages

```csharp
protected void Page_Init(object sender, EventArgs e)
{
    SessionHelper.RequireRole("Learner");
}
```

`RequireRole` sends the user to `Login.aspx` if nobody is logged in, or to their own dashboard if their role is wrong.

**Why in the master page?** All Learner pages use `Learner.Master` and all Management pages use `Management.Master`, so writing the check once protects every page, including when someone types the URL directly.

**Why `Page_Init` and not `Page_Load`?** The master page's `Page_Load` runs *after* the content page's `Page_Load`. `Page_Init` runs before it, so an unauthorised user is redirected before any page code reads data.

## 6. Form validation

Validation happens in two places:

1. **In the browser** with ASP.NET validators:
   - `RequiredFieldValidator` – field must not be empty
   - `RegularExpressionValidator` – email format, username format, password rule (8+ characters with a letter and a number)
   - `CompareValidator` – password and confirm password must match
   - `RangeValidator` – topic order must be a number from 1 to 100
2. **On the server**, every button handler starts with:

```csharp
if (!Page.IsValid)
{
    return;
}
```

Then the code checks things that need the database, such as a username or email that is already taken.

**Why both?** Browser validation gives instant feedback, but it can be switched off. The server check makes sure invalid data never reaches the database.

`ValidationGroup` is used on pages with more than one form (Profile, Forgot Password) so clicking one button only validates its own fields.

In `Web.config`, `UnobtrusiveValidationMode` is set to `None` so the validators work without jQuery files.

## 7. Settings in `Web.config`

```xml
<add key="QuizPassMark" value="60" />
<add key="QuizQuestionCount" value="5" />
<add key="ExamPassMark" value="70" />
<add key="ExamQuestionCount" value="20" />
<add key="RetakeWaitDays" value="7" />
<add key="ResetCodeMinutes" value="10" />
```

**Why:** The database contract says these numbers must be set centrally and not hard-coded differently by each member. The services read them with `ConfigurationManager.AppSettings`. For a demo, `RetakeWaitDays` can be set to `0` to show a retake without waiting a week.

## 8. Member 1 — Accounts and authentication

| File | What it does |
|---|---|
| `Register.aspx` | Validates input, checks duplicate username/email, calls `RegisterLearner` |
| `Login.aspx` | Accepts username **or** email, checks the hash, checks `AccountStatus`, signs in and redirects by role |
| `ForgotPassword.aspx` | 3 steps in 3 `Panel`s: email → code → new password |
| `Logout.aspx` | Clears the session and returns to Login |
| `Learner/Profile.aspx` | Edit name and email; change password after checking the current one |
| `Management/Learners.aspx` | Search learners, edit name/email, activate or deactivate |
| `Services/AuthService.cs` | Register, login, find by email, update password |
| `Services/UserService.cs` | Profile updates, learner list, account status |

Design decisions:

- **Public registration always inserts `Role = 'Learner'`** in the SQL itself, so nobody can make themselves Management from the form.
- **Inactive accounts cannot log in**, but their history is kept. That is why Management deactivates learners instead of deleting them.
- **Forgot password** creates a 6-digit code and keeps it in the Session with an expiry time (`ResetCodeMinutes`). The code is shown on screen because real email sending is out of scope for the prototype, as the specification allows. The code is never stored as the password.
- **The wrong-login message is the same for wrong username and wrong password** ("Invalid username or password") so an attacker cannot find out which usernames exist.

## 9. Member 2 — Learning content and topic quizzes

| File | What it does |
|---|---|
| `Learner/Topics.aspx` | Lists active topics with Completed / Available / Locked and a progress bar |
| `Learner/LearningMaterial.aspx` | Shows one topic's content (text, image, video) |
| `Learner/TopicQuiz.aspx` | One question at a time, Previous / Next / Submit |
| `Learner/TopicQuizResult.aspx` | Score, pass/fail, link to next topic or retry |
| `Management/LearningContent.aspx` | Add and edit topics |
| `Management/TopicQuizzes.aspx` | Add, edit and **delete** quiz questions per topic |
| `Services/LearningService.cs` | Topics, unlock logic, course completion |
| `Services/QuizService.cs` | Quiz questions, saving attempts, question CRUD |

### How topic locking works

There is **no Progress table**. Progress is worked out from `TopicQuizAttempts`:

```csharp
bool previousPassed = true;
foreach (DataRow row in topics.Rows)        // topics in TopicOrder
{
    if (currentId == topicId) return previousPassed;
    previousPassed = HasPassedTopic(userId, currentId);
}
```

The first topic is always open. Every other topic opens only if the topic before it has at least one `Pass` attempt.

**Why:** The database contract forbids a separate Progress table. Calculating it from the attempts means the progress can never disagree with the real quiz history.

`LearningMaterial.aspx` and `TopicQuiz.aspx` both call `IsTopicUnlocked`, so a learner cannot skip ahead by typing `?topicId=3` in the address bar.

### How the quiz works

- `GetQuizQuestions` picks `TOP (QuizQuestionCount)` active questions in random order (`ORDER BY NEWID()`).
- The questions and the learner's answers are kept in the **Session** while the quiz is running; the current question number is kept in **ViewState**.
- The correct answers stay on the server and are never sent to the browser.
- On Submit, the score is calculated from the submitted answers:

```csharp
decimal score = Math.Round((decimal)correct * 100 / questions.Count, 2);
```

- Every attempt is inserted into `TopicQuizAttempts`, pass or fail, so the history is kept.
- After saving, the page redirects to the result page. This stops the same answers being submitted twice if the user refreshes.

### Management content

- Topics are **not deleted** (only set to `Inactive`) because quiz attempts point to them.
- **Quiz questions are physically deleted** — this is the DELETE operation for the assignment. Attempts only store the score, not question IDs, so deleting a question never breaks history.
- Topic content allows HTML (headings, lists, images, video) so Management can format lessons. `ValidateRequestMode="Disabled"` is set **only on that one TextBox**; the rest of the site keeps ASP.NET's protection.
- Question and option text is passed through `Server.HtmlEncode` before it is shown, so text like `<b>` is displayed as text and not run as HTML.

## 10. Member 3 — Certification exam and results

| File | What it does |
|---|---|
| `Learner/ExamAccess.aspx` | Shows whether the learner can take the exam and why |
| `Learner/ExamGuidelines.aspx` | Rules + "I have read" checkbox before starting |
| `Learner/CertificationExam.aspx` | The exam, one question at a time |
| `Learner/ExamResult.aspx` | Score, attempt number, pass/fail |
| `Learner/Results.aspx` | History of exam attempts and quiz attempts |
| `Management/CertificationExam.aspx` | Add, edit and **delete** exam questions |
| `Management/LearnerResults.aspx` | All learners' results with search and Pass/Fail filter |
| `Services/ExamService.cs` | Access rules, questions, saving attempts, results |

### Exam access rules — `ExamService.GetAccessStatus`

| Situation | Status | Can take exam? |
|---|---|---|
| Already has a passing attempt | `Passed` | No |
| No attempts, all topics passed | `EligibleCourse` | Yes |
| No attempts, direct request approved | `EligibleDirect` | Yes |
| Last attempt failed, retake for **that attempt** approved | `EligibleRetake` | Yes |
| Last attempt failed, no approved retake | `RetakeRequired` | No |
| No attempts, course not finished, no approval | `NotEligible` | No |

**Why the retake is linked to the failed attempt:** a retake approval points to a specific `ExamAttemptID`. Once the learner takes the new attempt, the "last attempt" changes, so the old approval no longer applies. This is how **one approval gives exactly one new attempt** without adding an extra column.

**Protection:** `ExamGuidelines.aspx` and `CertificationExam.aspx` both check `CanTakeExam`, and the exam page also needs the guidelines checkbox (`Session["ExamGuidelinesAccepted"]`). Typing the exam URL directly sends the learner back to Exam Access.

### Attempt number

```csharp
int attemptNumber = CountAttempts(userId) + 1;
```

The attempt number is counted per learner, as the database contract says.

### Deleting exam questions

Like quiz questions, exam questions can be physically deleted. `ExamAttempts` only stores the score, so past results are never affected.

## 11. Member 4 — Requests, certificates and dashboards

| File | What it does |
|---|---|
| `Learner/Requests.aspx` | Submit a direct-exam request or a retake request; see request history |
| `Management/Requests.aspx` | Approve or reject pending requests; filter by status |
| `Learner/Certificate.aspx` | Shows a printable certificate |
| `Management/Certificates.aspx` | List and search issued certificates |
| `Learner/Dashboard.aspx`, `Management/Dashboard.aspx` | Summaries from real database data |
| `Services/RequestService.cs` | Direct and retake requests, reviews, counts |
| `Services/CertificateService.cs` | Issue and read certificates |

### Direct exam request rules

The learner can request only if they have **no exam attempts**, have **not completed the course** (they already have access then), and have **no pending or approved request**. After a rejection they may request again.

### Retake request rules (7-day rule)

```csharp
DateTime allowedDate = latest.AttemptDate.AddDays(requestService.GetRetakeWaitDays());
if (DateTime.Now < allowedDate) { ... not allowed yet ... }
```

The request must be for the learner's **latest failed attempt**, at least 7 days after it, with no pending or approved request already.

### Reviewing requests

```sql
UPDATE DirectExamRequests SET Status = @Status, ReviewedBy = @ReviewedBy, ReviewedDate = GETDATE()
WHERE RequestID = @RequestID AND Status = 'Pending'
```

`ReviewedBy` is the logged-in Management user's ID from the Session. The `AND Status = 'Pending'` part makes sure a request that was already reviewed cannot be changed again (for example by clicking twice).

### Certificates

- `IssueCertificate` first checks for an existing certificate, then looks for a passing exam attempt. With no pass, no certificate is created.
- It is called right after a passing exam is submitted, and again when the Certificate page opens. Because it checks first, it **never creates duplicates**. The `UNIQUE` constraint on `Certificates.ExamAttemptID` also blocks duplicates at the database level.
- The certificate number is `CF-<year>-<ExamAttemptID>`, e.g. `CF-2026-0002`. It is unique because the attempt ID is unique, and the learner cannot edit it.
- Certificate issuing lives in `CertificateService`, not in `ExamService`, because the responsibilities document gives certificates to Member 4.
- The certificate page has its own `<style>` block (internal CSS) and a print stylesheet that hides the menu when printing.

### Dashboards

Both dashboards only **summarise** (counts, latest attempts, status badges) and link to the detailed pages, as the specification asks. All numbers come from SQL `COUNT(*)` queries, not fixed values.

## 12. Shared UI — master pages, CSS and JavaScript

### Master pages

`Site.Master` (public), `Learner.Master` and `Management.Master` hold the `header`, `nav`, `main` and `footer`. Pages only fill in the `MainContent` placeholder, so the layout and menu are the same everywhere. Management uses a different header colour so it is clear which area you are in.

### CSS — three types, as the brief requires

| Type | Where |
|---|---|
| External | `Styles/site.css`, linked in every master page |
| Internal | `<style>` blocks in `Default.aspx` and `Learner/Certificate.aspx` |
| Inline | `style="..."` on a few elements, e.g. the progress bar width |

Responsive design uses CSS Grid for the card layout and `@media` queries: 3 columns on a laptop, 2 on a tablet, 1 on a phone, where the menu turns into a **Menu** button.

Status badges use one CSS class per database value (`badge-pass`, `badge-fail`, `badge-pending`, `badge-approved` ...). The page writes `badge-` + the value in lower case, so the colour always matches the status.

### JavaScript — `Scripts/site.js`

| Function | Used for |
|---|---|
| `toggleMenu()` | Opens/closes the phone menu |
| `confirmDelete()` | "Are you sure?" before deleting a question |
| `confirmSubmit()` | Confirms before submitting a quiz or exam |
| `checkAnswerSelected()` | Stops Next/Submit if no answer is chosen |
| `togglePassword()` | "Show password" checkbox on Login |
| `toggleStartButton()` | Enables "Start Exam" only after the guidelines box is ticked |
| `printPage()` | Prints the certificate |

The server checks the same things again (for example an unanswered question), so the site still works correctly if JavaScript is turned off.

## 13. Database design summary

- **9 tables only**, exactly as in `DATABASE_CONTRACT.md`. No Courses, Exams, Progress or Sessions tables, because there is one course, one exam, progress comes from attempts, and sessions live in ASP.NET Session.
- **`CHECK` constraints** allow only the fixed values (`Learner`/`Management`, `Active`/`Inactive`, `Pass`/`Fail`, `Pending`/`Approved`/`Rejected`, `A`–`D`).
- **`UNIQUE`** on `Users.Email`, `Users.Username`, `Topics.TopicOrder`, `Certificates.CertificateNumber` and `Certificates.ExamAttemptID`.
- **Foreign keys without cascade delete**, so history (attempts, requests, certificates) cannot be deleted by accident.
- **Defaults** (`GETDATE()`, `'Active'`, `'Pending'`) fill dates and statuses automatically.

## 14. Questions the lecturer may ask

| Question | Short answer |
|---|---|
| How do you stop SQL injection? | Every query uses `SqlParameter`; user input is never joined into SQL text. |
| How are passwords stored? | PBKDF2 hash with a random salt (`PasswordHelper`), never plain text. |
| How do you stop a learner opening Management pages? | `Management.Master` calls `RequireRole("Management")` in `Page_Init`. |
| How is the next topic unlocked? | `IsTopicUnlocked` checks for a `Pass` attempt on the previous topic. |
| Where is the DELETE operation? | Management → Topic Quizzes and Certification Exam → Delete question. |
| Why doesn't deleting a question break results? | Attempts store only the score, not question IDs. |
| How does one retake approval give one attempt? | The approval is tied to the failed `ExamAttemptID`; after a new attempt it no longer matches the latest attempt. |
| How is the score calculated? | Correct answers ÷ number of questions × 100, on the server after Submit. |
| How do you prevent duplicate certificates? | `IssueCertificate` checks first, plus a `UNIQUE` constraint on `ExamAttemptID`. |
| Where is client-side and server-side validation? | Validators in the `.aspx` pages, and `Page.IsValid` plus database checks in the code-behind. |
| Where is the multimedia? | Topic images in `Images/Learning/` and an embedded YouTube video in Topic 1. |
